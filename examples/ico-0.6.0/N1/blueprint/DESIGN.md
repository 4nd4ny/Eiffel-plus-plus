# Justification du harnais N0 ICO

Ce paquet organise le travail complet sur ICO ; il ne contient pas le produit. La demande de l’opérateur exige un harnais minimal mais conserve contrats, quatre responsabilités et compétences utiles. Le profil fixe le mandat ; ROUTAGE reprend les frontières constatées dans l’instantané étudié. Aucune politique d’entreprise supplémentaire n’a été présumée.

**Séparer consignes et copie mutable.** L’atelier fige référence, N0, contrat et fermeture de contrôles ; il permet seulement au code de travail d’évoluer. Cela évite la dérive de l’oracle observée dans une version précédente et conserve la vérifiabilité. Inclure tout le code dans le contexte permanent aurait alourdi les missions et rendu la préparation sensible aux dépendances installées. Le coût choisi est une copie complète à chaque gel ; ce n’est pas une optimisation pour des dépôts volumineux.

**Garder le projet complet, limiter le verdict.** La version diagnostique sélectionnait deux modules ; l’atelier conserve maintenant tous les fichiers de la copie de sources. Cela empêche d’appeler une tranche « livraison du projet ». Les onze sondes privées ne voient toujours que deux modules : la sélection demeure expérimentale et le déploiement non vérifié. Une revue du périmètre reste nécessaire même si toutes les empreintes concordent.

**Sept compétences, quatre responsabilités.** Spécifier, planifier, modifier le moteur, modifier l’interface, vérifier et décider ont des remises et des erreurs distinctes. La gouvernance prépare le mandat. Les fusionner en un texte universel diminuerait le nombre de fichiers mais chargerait les parcours UI dans un lot Import. N1 permet de ne charger que les compétences pertinentes ; aucune équipe de sept agents n’est imposée. Ici le même assistant réalise les rôles : auto-examen, pas audit indépendant.

**Conserver l’ancienne référence de contrôle.** Pour la comparaison privée, les sondes et le compilateur déjà figés sont réemployés. Cela garde la même question expérimentale. Le lanceur public exerce un cas fictif différent pour permettre une reproduction sans ICO. Ni la simulation ni les empreintes ne prouvent l’efficacité d’un LLM ; les constats sont consignés séparément après exécution.

**Justifier sans gonfler les consignes.** Ce document explique des décisions ; il ne change pas les obligations. Les notes de réalisation demandées à Produit portent uniquement sur les choix affectés par son changement, pas sur une reconstitution du raisonnement interne.

| Évolution métier | Adaptation concrète |
| --- | --- |
| Déploiement avec revue indépendante | ROLES, attributions et droits d’environnement ; désigner un autre acteur et vérifier la séparation. Les hashes seuls ne suffisent pas. |
| Nouveau format, fournisseur ou règle de conservation | STBL révise le contrat sourcé ; modifier-moteur et Audit révisent les cas avant d’ouvrir un nouveau lot. Conserver l’ancien résultat. |
| Exigence UI ou accessibilité renforcée | modifier-interface, parcours et critères ; fournir navigateur et environnement puis exécuter les contrôles manquants. |
| Politique de confidentialité ou réseau différente | Profil, contrat, checker et environnement ; une décision compétente doit préciser données et droits. Aucune permission ne découle de cette note. |
| Dépôt trop volumineux | Mesurer les copies, envisager un stockage adressé par contenu sans perdre l’identité complète ; rééprouver ajouts, suppressions et liens. |

La note est liée aux missions 0.6.0 : si elle change, leur référence devient STALE. Le résultat attendu est une meilleure lisibilité des compromis ; le bénéfice économique n’est pas établi.
