# Application du patron N2 à ICO

La demande impose une régénération complète et une comparaison, après plusieurs tentatives dont certaines avaient simplifié le dispositif au point de perdre son cycle de production. Le patron 0.6.0 relie maintenant les justifications aux instructions et aux missions. Nous l’appliquons en conservant les mécanismes antérieurs utiles, sans prétendre qu’une version plus récente est automatiquement meilleure.

La référence produit reste l’instantané privé déjà utilisé : changer simultanément le code aurait empêché d’attribuer les différences au harnais. N1 est retenu pour réutiliser la même méthode sur Import et Interface ; N0 est le paquet opérationnel. Le choix d’un seul acteur évite d’inventer une indépendance et permet l’exécution dans le mandat actuel ; une exigence d’audit séparé demanderait un autre environnement.

Les sources de conception sont les prompts N2 à la révision indiquée, les anciens harnais locaux, les observations de dérive des contrôles et les corrections de l’opérateur. Les spécifications privées orientent le routage sans être publiées. Le résultat public expose méthodes et compromis avec un cas synthétique ; l’évaluation ICO complète reste locale. Cette réduction de publication protège le produit, mais limite ce qu’un lecteur externe peut reproduire sur ICO.

Si le périmètre métier ou les droits de publication changent, revoir le brief et les décisions N1 avant de régénérer. Les notes décrivent les décisions retenues et leurs limites ; elles ne remplacent pas les contrats ni une revue indépendante.
